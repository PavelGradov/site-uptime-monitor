# Мониторинг доступности pavelgradov.ru

Автоматическая проверка `https://pavelgradov.ru/` через GitHub Actions без сторонних Python-пакетов и платных API.

## Возможности

- Проверки по cron каждые 5 минут; реальные запуски могут задерживаться или пропускаться GitHub.
- Два HTTP-запроса с паузой 2 секунды при неуспехе первой попытки.
- Дневные CSV-логи: `logs/YYYY-MM-DD.csv`, поля UTC-времени, URL, результат, HTTP-код, время ответа (мс), число попыток, ошибка.
- Текущий статус и счётчик ошибок в `status.json`.
- После двух последовательных неудачных запусков создаётся GitHub Issue, назначается пользователю PavelGradov, закрывается после восстановления.
- Сводка успешности сохранённых проверок: `python3 summarize.py --last 7`.

## Запуск

1. Откройте **Actions → Website uptime monitor → Run workflow** и выполните ручной запуск.
2. Убедитесь, что появились `status.json` и `logs/YYYY-MM-DD.csv`. Это признак успешной записи результата.
3. Проверьте в **Settings → Actions → General → Workflow permissions**, что разрешена запись, если push не проходит. Код задаёт `contents: write` и `issues: write`; включите Issues в настройках репозитория.
4. Для уведомлений по email от GitHub настройте оповещения о назначенных Issues и проверьте, что письма не отключены.

## Ограничения

GitHub Actions не гарантирует точное время запуска; возможны задержки и пропуски. Доля успешных запросов не равнозначна непрерывной доступности сайта. Репозиторий публичный — лог и Issues видны другим. GitHub Actions записывает новый git-коммит после каждой успешной проверки, поэтому история будет расти. Сайт с защитой от ботов может отвечать мониторингу иначе, чем обычному пользователю.

## Проверка

`python3 -m unittest discover -s tests -v`

Запустить локально: `python3 monitor.py`. Без `GH_TOKEN` и `GITHUB_REPOSITORY` уведомления не создаются.

Изменить сайт или получателя уведомлений можно в `.github/workflows/uptime.yml` через `MONITOR_URL` и `MONITOR_ASSIGNEE`.
